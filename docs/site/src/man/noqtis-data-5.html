NAME

noqtis-data — the noqtis data record, noqtis-data-1

DESCRIPTION

A data record is the file noqtis.data.json at the top of a capsule folder (noqtis-capsule(5)). It says where each data file of the capsule came from, what shape it has, how it was summarised, and what was done and checked with it. The record is an ordinary file of the capsule: the manifest lists it with its digests and the seal covers it, so noqtis-check(1) fails when it changes, and noqtis-data(1) (noqtis data check) checks the files against what it says.

The key words MUST, MUST NOT, SHOULD and MAY are to be read as in RFC 2119 and RFC 8174.

Canonical JSON

The record MUST be JSON (RFC 8259) in the canonical form of RFC 8785: UTF-8, no whitespace outside strings, object members sorted by the UTF-16 code units of their names, the minimal string escapes, and numbers as IEEE 754 doubles in the shortest form that round-trips, as ECMAScript writes them. A reader MUST reject a record that is not byte-identical to its own canonical form, has a duplicate member name, a string with U+0000 or not valid UTF-8, a number that is not finite, objects nested deeper than 32 levels, or more than 64 MiB. The same record is therefore the same bytes whichever program wrote it.

Types

string
at most 65,536 bytes.
path
a string naming a file of the capsule as the manifest does: relative, ‘/’ between folders, no empty, ‘.’ or ‘..’ segment, no backslash, colon or control character, at most 4,096 bytes, and not noqtis.json, noqtis.sig, noqtis.ers or noqtis.data.json.
hex
64 lower-case hex digits.
count
a whole number from 0 to 2^53.
time
‘YYYY-MM-DDTHH:MM:SSZ’, a valid UTC time.
date
‘YYYY-MM-DD’, a valid date of the proleptic Gregorian calendar.

The record

An object with format, the string ‘noqtis-data-1’, and any of the members below; no other member. A reader MUST reject a member it does not know, so that a record of a later format is refused rather than half-read. Arrays keyed by path (sources, schemas, stats) or name (checks) MUST be sorted by the bytes of the key, with no key twice; steps and commits keep the order they were written in. An array of objects MUST NOT be empty: a member with nothing in it is left out, so that each record has one form.

sources
Where each file came from. Each element: path (path, required), sha256 (hex, required: the file's SHA-256), size (count, required: its size in bytes), and optionally url (where it was fetched), resolver (an object: kind, one of ‘direct’, ‘ckan’, ‘socrata’, ‘arcgis’, ‘wayback’, required; and the strings base (the portal), id (the dataset), resource, format, and the count layer), retrieved (time), etag, modified (the server's ETag and Last-Modified, as sent), licence, publisher, title (strings), archived (an object: the archived copy's url, required, and its time), mirrors (an array of URLs with the same bytes), synthetic (true when the file is a generated stand-in for the real data; every report line about it says so).
schemas
The shape of a CSV file. Each element: path (required), kind (required: ‘csv’), delim (one byte, not a quote or line break; default ‘,’), header (boolean; default true), na (an array of strings that mean a missing value; default ‘’ and ‘NA’), rows (an object with counts min and max), columns and rules.

columns lists the columns in file order, each with name (required, no name twice), type (required: ‘int’, ‘real’, ‘text’, ‘date’ or ‘bool’), nulls (boolean: whether a missing value is allowed; default true), min and max (numbers for ‘int’ and ‘real’, dates for ‘date’), and set (for ‘text’: the values allowed).

rules are checks over a column or the table, each with kind and its arguments: ‘unique’ (col or cols: no value, or combination, twice), ‘notnull’ (col), ‘range’ (col, min and/or max), ‘set’ (col, set), ‘incr’ (col: each value at least the one before), ‘complete’ (col, share: at least that share not missing), ‘distinct’ (col, min and/or max distinct values), ‘rows’ and ‘cols’ (min and/or max).

stats
Summaries kept to detect drift later without keeping the data (noqtis-drift(1)). Each element: path (required), rows (count, required) and columns, each with name and n (required: the values not missing), nulls, and for a numeric column q (the quantile sketch: [value, count] pairs, value increasing, count the number of values at most it), edges and counts (the binning of the population stability index: increasing interior edges, bins closed on the right, one count more than edges), digits (nine counts of first significant digits 1 to 9); for a categorical column cats ([value, count] pairs sorted by value) and other (the count of values beyond those kept). noqtis-drift(1) defines how they are made and the error of each test made from them.
env
The environment of the run: strings os, arch, kernel, cpu, locale, tz, noqtis, build; runtime (an object: language required, version, packages, an array of {name, version, source} sorted by name); locks (lock files: an array of {path, sha256} sorted by path); rng (an object: kind required, and seed, a number or string).
steps
What was done to the data, in order: each with kind (required: ‘recode’, ‘filter’, ‘derive’, ‘script’ or ‘other’), and the strings from, to, note, script (a path) and sha256 (of a mapping or script).
checks
Results of checks made elsewhere (a published total, a falsification test): each with name (required), status (required: ‘pass’, ‘warn’ or ‘fail’), expected and observed (a number or string), tol (a number) and note. A check recorded as ‘fail’ fails its row in noqtis data check.
commits
Sealed commitments (a randomisation list, a pre-registration): each with kind (required: ‘randomisation’, ‘preregistration’ or ‘other’), created (time, required), alg (required: ‘sha3-256’), digest (hex, required), after (time: not to be revealed before) and label.
cite
How to cite the data: an object with title (required), authors (an array of strings), version, doi, url, licence and the count year.
