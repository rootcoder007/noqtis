NAME

noqtis-check — check a sealed capsule folder against its seal

SYNOPSIS

noqtis check [-p key.pub] [-j | --json] [--anchor der-file ...] [--only path ...] [--lineage input-dir ...] dir

noqtis check [-p key.pub] [-j | --json] [--anchor der-file ...] --proof file [dir]

DESCRIPTION

noqtis check checks the capsule dir (noqtis-capsule(5)): it reads and checks the seal noqtis.sig, checks that the SHA-256 of noqtis.json is the one in the seal, verifies the signature over the exact bytes of noqtis.json, then lists the folder and checks every listed file (present, a regular file, the size, the SHA-256 and the SHA3-256) and that no file is present that the manifest does not list.

It prints one row per check: a status (‘ok or ‘FAIL’’), the check's name and a detail, then a summary line

<dir>: OK (<n> checks passed)
or
<dir>: FAILED (<k> of <n> checks failed)

Without -p, the public key inside the seal is accepted: the check then shows that the files are those the key holder sealed, not who the key holder is. The ‘key’ row says so, and a note on standard error says to pass -p. With -p, the seal's key must be exactly the given key, and the seal's algorithm the one the key file names (a ‘key.alg’ row fails otherwise). Each option that takes a value may be given once.

Files are opened folder by folder from dir, never through a link, so a folder swapped for a link while the check runs fails it instead of being followed. A listed file whose size differs is reported without being read, and no file is read past one byte more than its listed size. File names and other text from the folder or a TSA are printed with control characters escaped (‘\x1b’), so they cannot rewrite the terminal.

With --anchor, the seal must carry an RFC 3161 timestamp over its signature whose token verifies under one of the anchors, with the TSA certificate's path valid at the token's genTime; the ‘timestamp’ row then shows the genTime. Without --anchor, a seal that carries a timestamp fails its ‘timestamp’ row: a timestamp that cannot be checked is never passed silently.

After the table, for each failed check, a line on standard error says what to do:

noqtis check: check: what to do
-p key.pub, --pub=key.pub
The public signature key the capsule must be sealed with.
-j, --json
Print one line of JSON instead of the table: 
{"capsule":"<dir>","ok":<bool>,"result":"<nqerr text>",
 "checks":[{"check":"<name>","ok":<bool>,"detail":"<text>"},...]}

A failed check also has ‘fix’, the text of the line on standard error.

--anchor der-file
A TSA trust anchor: the root or issuing certificate of a time-stamping authority, DER-encoded (convert PEM with ‘openssl x509 -outform DER’). Up to 32; one that verifies the token is enough.
--only path
Check only this listed file, up to 32 times: a partial check. The seal, the signature and the whole manifest are still checked; files not named are neither read nor needed, and files present but not listed are not looked for. ‘partial’ rows say so, so a partial pass is never mistaken for a full one. A named path the manifest does not list fails its ‘file’ row.
--lineage input-dir
The folder of a capsule that may be one of the inputs of dir (a format 2 capsule sealed with noqtis-seal(1) --input), up to 32 times. Each input is found among them by its id, the SHA-256 of the bytes its seal signs, and checked in full without a pinned key; its own inputs are looked for in the same folders, to 64 levels. One ‘lineage’ row per input says whether it was found and checks.
--proof file
Check a proof made by noqtis-prove(1) instead of a folder: the seal in the proof, its signature over the manifest's head, and each proven entry's Merkle audit path to the root the head signs (‘proof.entry’). With dir, the proven files there are also checked against their entries, and a ‘partial’ row says the capsule's other files are not in the proof. --only and --lineage do not apply.

Checks

The row names are stable, for scripts:

seal.read
noqtis.sig exists, is a regular file (not a link) and is at most 1 MiB.
seal.parse, seal.canonical
It is a JSON object in canonical form (RFC 8785).
seal.fields
It has exactly the fields of ‘noqtis-seal-1’, with the right types; ‘manifest_sha256’ is 64 lower-case hex digits.
seal.format
‘format’ is ‘noqtis-seal-1’.
seal.alg
‘alg’ names a signature algorithm noqtis knows.
seal.context
‘context’ is at most 255 bytes.
seal.key, seal.signature
‘public_key’ and ‘signature’ are base64 of the algorithm's sizes.
manifest.read
noqtis.json exists, is a regular file and is at most 512 MiB.
manifest.digest
Its SHA-256 is the seal's ‘manifest_sha256’.
key
Whether the key was pinned with -p.
signature
The signature verifies over the exact bytes of noqtis.json.
timestamp
Present only when the seal has a timestamp or --anchor was given.
folder
The folder could be listed within the limits.
file
One row per listed file.
manifest.parse, manifest.canonical, manifest.fields
The manifest is canonical JSON with exactly the fields of ‘noqtis-capsule-1’.
manifest.format, manifest.created, manifest.order
‘format’ is ‘noqtis-capsule-1’ (or ‘noqtis-capsule-2’ under a ‘noqtis-seal-2’ seal), ‘created’ is an RFC 3339 UTC time, and the files are sorted by path with no repeats.
manifest.merkle
Format 2: the Merkle tree over the file entries has the root and leaf count the signed head gives.
lineage
With --lineage: one row per input of the capsule.
partial
With --only or --proof: what the check left out; never a failure.
proof.parse, proof.canonical, proof.fields, proof.entry
With --proof: the proof is canonical JSON with exactly the fields of ‘noqtis-proof-1’, and each entry's audit path leads to the signed root.
path
One row per refused, non-normal, duplicate or too long path, and per two paths that differ only in case.
extra
One row per regular file present but not listed.
unsafe
One row per link, reparse point, special file or refused name in the folder.

EXIT STATUS

0
Every check passed.
1
A check failed (the files changed, the seal or manifest is damaged or not signed by key.pub).
2
A usage error, dir does not exist, a key that is not a public signature key, an anchor that cannot be read or is not DER, or a library error such as running out of memory.

EXAMPLES

$ noqtis check -p me.pub results
      check               detail
ok    seal.read           noqtis.sig
...
ok    signature           ML-DSA-65 signature over noqtis.json is valid
ok    folder              listed
ok    file                data/in.csv
ok    file                report.txt
...
ok    manifest.order      files sorted by path, no repeats
results: OK (22 checks passed)

After a file was changed and one added:

$ noqtis check -p me.pub results; echo $?
...
FAIL  file                report.txt: size differs
...
FAIL  extra               new.txt: not in the manifest
results: FAILED (2 of 23 checks failed)
noqtis check: file: a sealed file changed after sealing: restore it from the original, or seal the folder again if the change was intended
noqtis check: extra: a file was added after sealing: remove it, or seal the folder again to include it
1

A timestamped capsule, against the TSA's root certificate:

$ noqtis check -p me.pub --anchor digicert.der results
...
ok    timestamp           RFC 3161 token over the signature verifies under a TSA anchor; genTime 2026-10-29T09:34:03Z
...
results: OK (23 checks passed)

Only one file of a format 2 capsule, and its inputs:

$ noqtis check -p me.pub --only data/in.csv results
$ noqtis check -p me.pub --lineage raw results

In CI, keeping only the failed rows:

$ noqtis check --json -p me.pub results |
    jq -r '.checks[] | select(.ok | not) | .detail'
report.txt: size differs
new.txt: not in the manifest
